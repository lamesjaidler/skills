# continuous-discovery

The habits of *Continuous Discovery Habits* — weekly customer touchpoints, run by the product trio, in pursuit of an outcome — are now Claude Code skills. Each skill coaches one step of the discovery loop: defining the outcome to chase, talking to customers weekly, mapping the space of opportunities, picking which need to address, ideating and narrowing solutions, de-risking them, and reflecting on progress each week.

Based on *Continuous Discovery Habits* by Teresa Torres. This plugin is an independent implementation of the book's methodology and is **not affiliated with, endorsed by, or approved by Teresa Torres or Product Talk**.

## Start here

**Begin with continuous-interviewing** — the keystone habit. Get a weekly customer conversation happening with your product trio first; the rest of the practice grows around it. Once you have a rhythm, add `defining-outcomes` to land on a durable outcome to guide the loop. Then let the discovery loop pull in the rest as you harvest opportunities, prioritize, ideate, test, and tune your work weekly.

## Skills

| Skill | Use it when |
|-------|-----------|
| `defining-outcomes` | Starting continuous discovery, setting or revising a product outcome for a product trio, or when a stated goal is a feature to ship or a single-feature usage metric. |
| `continuous-interviewing` | Preparing for a customer interview or synthesizing one after—building a discussion guide or a team snapshot. |
| `mapping-the-opportunity-space` | Turning interview snapshots into opportunities or building and updating the opportunity solution tree. |
| `prioritizing-opportunities` | Choosing which opportunity to pursue next—comparing siblings on the tree and descending. |
| `ideating-solutions` | Generating solution ideas for a target opportunity or narrowing ideas down to a set worth testing. |
| `ideation-swarm` | Widening a thin idea pool for a target opportunity—three persona subagents ideate in isolation, see the pool, ideate again. Output is agent-authored stimulus for the trio's own ideation, never a shortlist. |
| `testing-assumptions` | De-risking candidate solutions before building—surfacing assumptions, designing quick tests, and recording results. |
| `running-weekly-touchpoints` | Running the team's weekly discovery ritual—checking staleness, measurement, and what to do after a test result. |

## State

Skills keep state in your product repository under `discovery/`. The directory layout, file naming, and exact section headings are defined in [`discovery-layout.md`](discovery-layout.md) — read it once and follow it exactly.
